# To_Do_List — 남은 작업

이 문서는 **환경 구축 기록이 작성된 시점(2026-08-10)에 남아 있던 일**을 적는다.
배경과 설계는 `README.md`, 사이클 절차는 `PROMPT.md`, 행동 규칙은 `AGENTS.md` 에 있다.

`runs/`와 `traces/`는 Git에서 제외되므로 clone에는 증거 파일이 없고 로컬 존재 여부도
환경마다 다르다. 따라서 아래 수치·후보·`verify` 결과는 그 자체로 현재 상태의 증거가

있는지 실제 파일로 확인하고 `verify` 결과를 확인한다. 없거나 검증에 실패할 때만 같은
spec으로 다시 실행한다.

각 항목에는 **왜 필요한지**와 **무엇을 보면 끝났다고 할 수 있는지(완료 판정)** 를 적었다.

## B. 하드웨어 없이 확인·검증할 수 있는 것

### B1. `remask()` 전이 누설 후보의 원인 규명 ★ 최우선

과거 실행 기록이 결함 후보로 지목한 위치다. 결론을 내려면 먼저 실제 결과 파일과 manifest를
검증한다. 파일이 없거나 검증에 실패하면 재현 명령으로 후보를 다시 산출하고, 이어서 사람이
소스와 기계어를 검토해야 한다.

**과거 기록에 남은 관측**(002, 순열 20회)

| 항목 | 값 |
|---|---|
| 위치 | `0x81be`, 성분 `hd_reg`(레지스터 전이), 명령어 #4671·#5267 |
| 소스 | `workspace/iut/masked-aes-c/aes.c`의 `remask()` 루프 |
| 종속 민감값 | `add_rk0`(= p⊕k), `sbox_out`, `round1` |
| 통계량 | **∞** — 클래스 내 분산 0, 즉 완전 결정적 종속 |
| 구간 | CipherMasked (보호 대상 구간 안) |

**기계어**

```
81be:  ldrb  r4, [r0, #0]     ← state 바이트 로드
81c0:  eors  r4, r1
81c2:  strb  r4, [r0, #0]
81c4:  ldrb  r4, [r0, #1]     ← 같은 r4 재사용
```

`remask()` 의 루프가 **`r4` 를 매 바이트 재사용**한다. 두 share 가 같은 레지스터를
연달아 지나면 `HD = HW(share1 ^ share2) = HW(민감값)` 이 되는데, 그것이 이 프로젝트가
찾으려던 결함 유형 그대로다.

**아직 말할 수 없는 것** — 도구는 "여기를 보라" 까지만 했다.

- 정확히 **어느 두 값**이 XOR 되어 민감값이 되는지
- 이것이 실제 공격으로 이어지는지 — **공격자 관점 CPA 는 1/16 으로 실패했다.** 즉 이
  누설이 곧 키 복구를 뜻하지는 않는다
- 고칠 값어치가 있는지, 고친다면 어떻게(레지스터 분리, 배리어, 순서 변경)

**완료 판정**: 원인을 소스 수준에서 설명한 문서와, 수정 여부에 대한 판단이 남는다.
수정한다면 수정 전후 데이터셋으로 `soundness` 를 다시 돌려 그 지점이 사라지는지 확인한다.

**재현**

```bash
docker exec -it chipwhisperer-kor bash
cd "/workspace/[extra] Physical-AI-SCA"
arm-none-eabi-objdump -d --start-address=0x81b0 --stop-address=0x81e0 \
  emul_harness/build/masked-aes-c.elf
python3 -c "
from physai import spec as sm, soundness, paths
sp = sm.load('exp/002_emul_masked.yaml')
r = soundness.run(paths.TRACES/'002_emul_masked.h5', sp, n_traces=4000, n_perm=20,
                  sensitive_window=(0,10147), labels=('add_rk0','sbox_out','round1'))
print(r['candidates'])"
```

## C. 계획과 달라진 점 (기록)

구현하며 사실을 확인해 계획을 바꾼 것들이다. 판단 근거를 남긴다.

| 계획 | 실제 | 이유 |
|---|---|---|
| 빌드 플래그 `-O2` | **`-Os`** | 실측 펌웨어가 `-Os` 다(`workspace/base/Makefile.inc`). 최적화 수준이 전이 누설을 만들고 없애므로, 플래그가 다르면 다른 구현을 분석하는 셈이다 |
| `templates/{01,02,03}.md` | **만들지 않음** | `report.py` 가 문서를 코드로 조립한다. 대조표·수치·조건부 절이 대부분이라 템플릿과 코드로 나누면 두 곳을 고쳐야 한다. 쓰이지 않는 `TEMPLATES` 상수는 삭제했다 |
| `contracts/results.schema.json` | **만들지 않음** | 소비자가 없다. `results.json` 의 계약은 `grades` 필드와 `json_conventions` 가 문서화하고 있으며, 검증하는 코드가 생기면 그때 만든다(AGENTS.md 원칙 2) |
| SPA가 `pass`/`fail` 판정 | **판정하지 않음** | 잡음 바닥이 0인 결정적 채널에서 "키가 다르면 트레이스도 다르다"는 거의 항상 참이라, 그것만으로 fail을 내면 **어떤 구현도 통과할 수 없는** 판별력 없는 시험이 된다. 관측값을 `statistical_verdict`로 보고하고 판정은 사람이 한다 |
| 앞 시험 fail 시 뒤 시험 중단 | **계속 수행** | §7.3.2 의 순서는 `should` 이고 §8.1 의 "셋 다 평가" 는 `shall` 이다. 건너뛰면 §8.1 을 어기고 "어디가 얼마나 새는지" 정보를 잃는다 |
| A.2.5 를 `미준수` 로 예상 | **`미기록`** 으로 나옴 | 1.0 데이터셋에는 `preprocessing_average_n` 필드 자체가 없다. "안 지켰다" 가 아니라 "모른다" 가 정확하다 |

## D. 이 환경을 쓸 때 잊지 말 것

- **`inconclusive` 는 "안전" 이 아니다.** 트레이스 수 부족이나 육안 미결은 판정할 수 없다는 뜻이다.
- **"검출 없음"은 같은 실행 조건의 대조군 증거와 함께만 의미가 있다.** `exp/001`은 그
  증거를 만들기 위한 명세이며, 검증 가능한 결과 번들이 없을 때 새 사이클에서 먼저 실행한다.
- **경계 밖 검출을 감추지 않는다.** Annex H 에 따라 fail 로 세지 않되 별도 목록으로 보고한다.
- **에뮬에서 깨끗해도 실물에서 샐 수 있다.** 세 관측은 대체재가 아니라 상보재다.
- **"검증 완료" 라고 쓰지 않는다.** 이 환경이 낼 수 있는 것은 사전 진단 결과다.
