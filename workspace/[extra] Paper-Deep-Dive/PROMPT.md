# PROMPT — 공통 실행 계약

3-AI 공통. 역할 장문·패킷 필드는 반복하지 않는다.
→ 역할: `roles/<role_id>/` · 인계: `ARTIFACT_CONTRACTS.md` · 바인딩: `AI_ROSTER.md`

---

## 0. 두 명제 — 프로젝트 전체를 관통한다

모든 판단의 상위 기준. 충돌하면 아래 두 명제가 이긴다.

### 0.1 자기완결성 (Self-contained)

**이 폴더만 넘겨받은 제3의 AI가, 외부 정보 없이 곧바로 이어서 작업할 수 있어야 한다.**

| # | 규칙 |
|---|------|
| S1 | **폴더 밖 의존 금지** — 지침·상태·근거는 이 폴더 안에서 모두 해결된다. 외부 대화 로그·타 저장소·이전 세션 기억을 전제하지 않는다. |
| S2 | **절대경로 금지** — 모든 경로는 **프로젝트 루트 기준 상대경로**. 루트 = 이 `README.md`가 있는 폴더. 환경 의존 절대경로는 `.Intermediate_Artifacts/SYNC.md`(운영 지침 아님)에만 둔다. |
| S3 | **대화는 휘발된다 — 양방향.** ① 사용자→AI: 대화로 받은 지시·승인·피드백은 **그 턴에** 폴더 안(`DECISIONS` / 자기 `To_Do_<Role>.md` / `HANDOFF`)에 기록해야 유효하다. ② AI→사용자: **보고·판정·제안의 SSOT는 자기 `To_Do_<Role>.md`다.** 채팅 답변은 그 파일 내용의 전달일 뿐이며, **채팅에만 있는 보고는 수행하지 않은 것으로 간주한다.** |
| S4 | **외부 자산 내부화** — 외부에서 가져온 사실·자료는 출처·버전·해시와 함께 `Papers/`에 자산으로 남긴다 (§4). 링크만 남기지 않는다. |
| S5 | **고아 파일 금지** — 폴더 안 모든 파일은 `README.md` 문서 계층 표에서 **운영 / 역사 / 산출물** 중 하나로 분류된다. 분류 없는 파일을 만들지 않는다. |
| S6 | **판정** — 문서를 고칠 때마다 “이 폴더만 받은 새 AI가 이것만 읽고 같은 결론에 도달하는가”를 자문한다. 아니면 그 문서가 결함이다. |
| S7 | **사본은 휘발된다 — 작업 루트는 하나.** 사본·worktree가 여럿 존재할 수 있고, **모든 사본이 자기완결적이라 겉으로는 구별되지 않는다**(S1의 대가). 그러므로 **세션 시작 시 자기 작업 디렉터리를 `.Intermediate_Artifacts/SYNC.md`의 작업 루트와 대조한다.** 다르면 **아무것도 쓰지 않고** 사용자에게 알린다. 다른 사본에 쓴 것은 **없는 것으로 간주한다**(S3와 같은 원리 — 기록 위치가 틀리면 무효). |

사용자는 편의상 채팅으로 바로 명령할 수 있다. 그러나 **AI의 보고는 접점 파일만으로 완결**되어야 한다 — 사용자가 `To_Do_*.md`만 열어도 무슨 일이 있었고 무엇을 해야 하는지 알 수 있어야 한다.

### 0.2 단순성 (Simplicity is the ultimate sophistication)

**기교를 덜어내고 본질만 남긴다.** 규칙을 늘려 문제를 덮지 말고, 구조를 바꿔 문제가 생기지 않게 한다.

| # | 규칙 |
|---|------|
| P1 | **한 사실은 한 곳에** — SSOT. 같은 내용을 두 파일에 적지 않는다. 고칠 곳이 둘이면 이미 틀렸다. |
| P2 | **규칙보다 구조** — 규칙을 더하기 전에 구조로 없앨 수 있는지 먼저 본다. (예: D40이 접점을 역할별로 나누자 “덮어쓰기 금지” 규칙 3줄이 통째로 사라졌다) |
| P3 | **기존 것을 먼저 쓴다** — 새 상태·새 파일·새 계층을 만들기 전에 이미 있는 것을 재사용한다. (예: D42의 director 게이트는 기존 `gate` 열과 `awaiting_approval`만으로 구현됐다) |
| P4 | **장식 금지** — 쓰이지 않는 파일·섹션·필드는 지운다. 남길 이유를 대지 못하면 삭제한다. |
| P5 | **표와 포인터** — 장문 복붙 금지. 설명은 한 곳에 두고 나머지는 가리킨다. |

## 1. 목표

논문·관련 자산을 검증 가능하게 모으고, 근거 위치와 함께 심층 분석한 뒤, 한글 Marp로 옮긴다.
본문 분석은 **비요약·비상상**. 레퍼런스는 **1-deep 요약** 허용.

## 2. 역할 구도 (role_id 기준)

```text
                 director  ── 규격 정의 · 단계 승인/반려 · 충돌 최종 결정
                    ┆ (호출 시에만 · 파이프라인 외부)
curator ──────→ analyst ──────→ producer ──────→ 사용자
수집·검증·정리    분석·해석      구조화·시각화·Marp
```

서비스명(Codex/Grok/Agy/Claude)은 `AI_ROSTER.md` 바인딩일 뿐. **행동 분기는 role_id로만.**

`director`는 **상시가 아니다.** 호출 시점은 `roles/director/ROLE.md`. 호출되지 않은 동안 세 역할은 정상 진행하며, 분석 **단위** 승인은 종전대로 사용자 게이트(G1)다.

## 3. 원칙 (전원)

0. **자기완결성 · 단순성** — 두 명제가 최우선. §0 (S1–S6 · P1–P5).
1. **자기 역할만** — 타 역할 핵심 업무·소유 파일 대행/개서 금지.
2. **입력 존중** — 타 산출물은 입력; 오류는 `HANDOFF`로 회송.
3. **근거 추적** — `paper_id → asset → 원문위치 → 분석단위 → handoff_id → slide`.
4. **사용자 접점은 자기 파일 하나** — `To_Do_<Role>.md` only (§8). 미결 판단 **1건/파일(최대 2)**.
5. **채팅 키워드는 둘뿐** — 파일명이 없어도 자기 role_id로 대상이 정해진다 (`AI_ROSTER`).

   **`계속`** = 자기 `To_Do_<Role>.md`의 **`## 사용자 답변 칸` 이하**만 사용자 지시로 사용.
   답변 칸이 비어 있으면 **새 사용자 지시가 없다는 뜻일 뿐이다.** 그때도 `HANDOFF`의 **자기 대상 `ready`는 처리한다**(§7.2). 둘 다 없을 때만 대기·보고.

   **`초기화`** = **이전 대화·세션 기억을 전부 버리고, 폴더만으로 자기 상태를 처음부터 재구성**한 뒤 보고한다. 절차·응답 양식은 `BOOTSTRAP_PROMPT.md`와 같다 (**재부트스트랩**).
   ⚠️ **파일을 지우거나 되돌리는 명령이 아니다.** 초기화 대상은 **AI의 인식뿐**이며 폴더 내용은 손대지 않는다.
   재구성 결과가 문서와 어긋나면 그 자체가 **자기완결성 결함**이므로 보고한다(S6).
   재구성 결과는 자기 `To_Do_<Role>.md`의 `지금 상태`에 **응답 양식 5항목 그대로** 남긴다 — 특히 **작업 루트 대조 결과**를 빠뜨리지 않는다.
   **초기화 중에는 handoff를 소비하지 않는다** — 자기 대상 `ready`는 목록으로 보고만 하고, 처리는 다음 `계속`에서. 연구 작업도 착수하지 않고 대기한다.
6. **ready만 소비** — `awaiting_approval`·미래 계획은 소비 금지 (`ARTIFACT_CONTRACTS`).
7. **Markdown 소통** — 사용자 검토·논의는 Markdown 문서로. CLI 출력으로 내용 검토를 유도하지 않는다 (D12).

## 6. 지침 우선순위

1. 현재 대화의 명시적 사용자 요청; 연구 승인·피드백은 자기 `To_Do_<Role>.md` 답변 칸
2. 자기 `To_Do_<Role>.md` 최신 사용자 지시 (답변 칸)
3. `DECISIONS.md` (번호 큰 쪽이 동일 주제 충돌 시 우선)
4. 본 `PROMPT.md`
5. `AI_ROSTER.md`
6. `roles/<role_id>/*`
7. `ARTIFACT_CONTRACTS.md` · `HANDOFF.md`
8. `README.md` (지도만)

현재 대화와 답변 칸이 충돌하고 어느 쪽이 최신인지 불명확하면 추측하지 않고 사용자에게 확인한다.

`director`의 조정·최종 결정은 **3위 `DECISIONS`의 D-기록으로 효력을 갖는다.** 따라서 **사용자 > director > 나머지 계약 문서**이며, 기록되지 않은 director 판단은 효력이 없다(S3). D-기록에는 출처가 `사용자`인지 `director`인지 적는다.

`README.md`가 **역사**로 분류한 파일은 폐기 계층 — 구조·경로·의무를 따르지 않는다. 배너로 표시되어 있다.

## 7. 세션 절차

0. **작업 루트 확인 (제일 먼저).** 자기 작업 디렉터리가 `.Intermediate_Artifacts/SYNC.md`의 작업 루트와 같은가? 다르면 **읽기만 하고 쓰지 않으며**, 사용자에게 알리고 대기한다 (S7).
1. 최초/구조 변경 시 `README`; 매 세션 본 파일 → `AI_ROSTER` → 자기 `roles/<id>/`; 인계 시 `ARTIFACT_CONTRACTS`.
2. 자기 `To_Do_<Role>.md` 답변 칸 + `HANDOFF`의 **자기 대상 `ready`** 만.
3. 역할 밖 요청 → 거절 + 올바른 역할로 handoff (타 역할 접점 파일에 쓰지 않는다).
4. 종료 시: 소유 파일·관련 handoff·(필요 시) MILESTONES 한 줄. **대화에서만 정해진 것을 남기지 않는다** (S3).
5. **종료 전 작업 루트에 반영됐는지 확인.** 임시 작업 공간에서 작업했다면 턴이 끝나기 전에 작업 루트로 옮긴다 — 옮기지 않은 것은 수행하지 않은 것이다 (S7).

## 8. 접점·공유 파일 쓰기

### 8.1 사용자 접점 — 역할별 **단독 쓰기**

| 파일 | 단독 쓰기 | 사용자 |
|------|-----------|--------|
| `To_Do_Curator.md` | `curator` | 답변 칸 |
| `To_Do_Analyst.md` | `analyst` | 답변 칸 |
| `To_Do_Producer.md` | `producer` | 답변 칸 |
| `To_Do_Director.md` | `director` | 답변 칸 (상시 아님 — 보통 비어 있음) |

- **자기 파일만** 읽고 쓴다. 타 역할 접점 파일은 열지 않는다 — 역할 간 조율은 `HANDOFF.md`.
  - 예외: `director`는 **충돌 조정에 필요할 때 타 역할 접점 파일을 읽을 수 있다.** 쓰기는 여전히 금지 — 읽기는 오염을 만들지 않는다.
- 미결 질문은 자기 파일 안에서 **1건(최대 2)**. 파일이 역할당 하나이므로 대기·덮어쓰기 규칙은 없다.
- 답변 칸은 **처리한 뒤 내용만 비운다.** "파악하라·검토하라"처럼 **산출물 변경이 없는 지시도 처리에 포함**된다 — 읽고 끝내지 말고 비우고 `최근 완료`에 한 줄 남긴다(S3: 기록되지 않으면 수행하지 않은 것).
- 고정 섹션은 **삭제·이름 변경 금지**: `지금 상태` · `지금 할 일 (사용자)` · `다음에 올 일` · `최근 완료` · `사용자 답변 칸`.
- **`지금 할 일 (사용자)`는 사용자가 실제로 할 행동·판단이 있으면 반드시 채운다.** 채팅으로 이미 말했다는 이유로 `0건`으로 두지 않는다 (S3②). `0건`은 정말로 사용자가 할 일이 없을 때만 쓴다.
- **`최근 완료`는 사용자가 이 파일만 읽고 무슨 일이 있었는지 알 수 있을 만큼** 적는다. 상세는 `DECISIONS`의 D-번호로 가리킨다 (P5).
- **답변 칸의 코드 펜스는 구조물이다.** 펜스를 지우면 사용자가 쓸 자리가 사라진다. 비운 상태 = **펜스는 남기고 안은 비운다.** 안내 문구(`(여기에 기입)`)는 있어도 없어도 된다.

### 8.2 공유 파일 (행·섹션 규칙)

| 파일 | 규칙 |
|------|------|
| `HANDOFF.md` | 송신: 행 추가/`draft`→`ready`; 수신: `in_progress`/`done`/`blocked`. **director 게이트**: `awaiting_approval` → `ready`(승인) \| `blocked`(반려) |
| `MILESTONES`·`ROADMAP` | 자기 책임 행만 갱신. **M-항목 `done` 전환은 director 승인 handoff를 근거로 한다** |

공통 정책 문서(`README`·`PROMPT`·`AI_ROSTER`·`ARTIFACT_CONTRACTS`·`BOOTSTRAP`·`AGENTS`·`DECISIONS`)와 `CROSS_CHECK`는 **더 이상 공유가 아니다** — `director` 단독 쓰기(D42). 세 역할은 자기 역할 문서만 고치거나 `to: director` handoff로 개정을 제안한다. 세 AI에 동일하게 보낸 일반 검수 요청은 소유권을 옮기지 않는다.

### 8.3 director 게이트 — 새 상태를 만들지 않는다

기존 `gate` 열과 `awaiting_approval`·`blocked`를 그대로 쓴다.

1. 송신 역할: 단계 종료 산출물을 `awaiting_approval` + `gate: director`로 올린다.
2. `director`: 규격 대조 → **승인** `ready` (다음 역할 소비 가능) / **반려** `blocked` + 사유 + 보완 방향 + 재개 조건 → 송신 역할 회송.
3. director는 산출물을 직접 고치지 않는다. 수정은 담당 역할이 한다.
4. 단위별 연구 승인(G1)은 사용자 게이트이며 director를 거치지 않는다 — **이중 게이트로 파이프라인을 막지 않는다.**

## 9. 한 줄

> 역할 나누고, ready만 받고, 근거 남기고, **자기 To_Do로만** 묻는다.
